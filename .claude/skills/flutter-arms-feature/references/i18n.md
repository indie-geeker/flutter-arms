# i18n via slang

## Workflow

1. Edit BOTH `lib/i18n/en.i18n.json` AND `lib/i18n/zh.i18n.json`. Keep the structure symmetric — if you add a key to one, add it to the other.
2. Run `dart run slang` (or `tool/gen.sh`) to regenerate `strings.g.dart`.
3. Access in widgets via `context.t.<path>`:

   ```dart
   Text(context.t.auth.welcomeBack);
   ```

`context.t` is a slang-generated extension that returns the current locale's strings. No BuildContext lookup for `AppLocalizations` needed.

## Adding a feature namespace

Both files need the same shape. Append to each:

```json
{
  "auth": { /* ... */ },
  "settings": {
    "title": "Settings",
    "notifications": "Notifications",
    "language": "Language"
  }
}
```

Then `context.t.settings.title`.

## Dynamic parameters

slang uses `{paramName}` inside the string:

```json
{
  "greeting": "Hello, {name}!",
  "itemCount": "{count, plural, =0{No items} =1{1 item} other{{count} items}}"
}
```

In Dart:

```dart
Text(context.t.greeting(name: user.name));
Text(context.t.itemCount(count: items.length));
```

## The `errors` namespace (critical)

Every `FailureCode` value MUST have a matching key under `errors.<code>`:

```json
{
  "errors": {
    "network": "Network connection failed",
    "timeout": "Request timed out",
    "badResponse": "Server error",
    "auth": "Session expired, please sign in again",
    "validation": "Invalid input",
    "cancelled": "Request cancelled",
    "unknown": "Something went wrong"
  }
}
```

`context.failureMessage(failure)` uses this:

- For `badResponse` and `validation` → tries `failure.detail` first (server message or validator hint), falls back to `t.errors.<code>` when detail is null.
- For everything else → always `t.errors.<code>`.

If you add a new `FailureCode`, add the matching key to both JSON files AND update the switch in `context.failureMessage` (`lib/core/extensions/build_context_ext.dart`).

## Accessing current locale in a Notifier

```dart
final currentLocale = ref.watch(localeProvider);  // AppLocale enum
```

`localeProvider` is in `lib/core/locale/locale_notifier.dart`. Change via `ref.read(localeProvider.notifier).setLocale(AppLocale.zh)`.

## What to AVOID

- `AppLocalizations.of(context)` — this project uses slang, not intl-based gen. There is no ARB file.
- Hardcoded user-facing strings in Dart. If you see a literal in a widget, move it to both JSON files and regenerate.
- Asymmetric JSON — if you add a key to `en.i18n.json` but forget `zh.i18n.json` (or vice versa), slang will throw at codegen time.
- Referencing `t.path` where `t` is stale — always go through `context.t` inside `build()` so locale changes re-render correctly.
